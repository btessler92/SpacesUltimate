Switch Sampling Notes - Built-in Screen, May 12 2026

Test setup: one visible built-in Retina display. The installed app reported accessibilityTrusted: false, so /switch?space=N returned ok: false. Switching below used macOS Control+Left/Right via System Events, then sampled /status.

Main finding: Dock's Display Identifier == "Main" current-space record stayed pinned to Desktop 4 across the walk. Visible-window matching moved with the visible desktop when windows existed, but it has no answer on empty desktops. That means the current live app can still show stale D4 when window evidence is absent.

Interpretation: Current Space.uuid from the Main Dock record is not the best current source on this machine right now. It looks like a persisted or disconnected monitor state, not a live active Space signal. The cleanest observed live signal was Space Properties.windows plus CGWindowListCopyWindowInfo, but it is inherently incomplete when the active desktop has no normal windows.

Next candidate to investigate: another live source for the frontmost Space that does not depend on windows, such as a more current Dock/window-server state source or an accessibility/Mission Control signal. Until then, the menu bar should probably show unknown instead of trusting Main when there is no exact display UUID match and no window match.
